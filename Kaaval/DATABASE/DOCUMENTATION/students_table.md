# KAAVAL – Students Table Design

## 1. Table Name

`students`

## 2. Purpose

The students table stores the basic information of students registered in the KAAVAL attendance system.

## 3. Table Columns

| Column Name | Data Type | Constraint | Purpose |
|---|---|---|---|
| student_id | BIGINT | PRIMARY KEY, IDENTITY | Unique ID for each student |
| admission_number | VARCHAR(30) | UNIQUE, NOT NULL | Student admission number |
| full_name | VARCHAR(120) | NOT NULL | Student's full name |
| section_id | BIGINT | FOREIGN KEY | Student's section reference |
| fingerprint_id | INTEGER | UNIQUE, NULL allowed | Fingerprint sensor slot reference |
| date_of_admission | DATE | NULL allowed | Date of admission |
| is_active | BOOLEAN | DEFAULT TRUE | Whether the student is active |
| created_at | TIMESTAMPTZ | DEFAULT CURRENT_TIMESTAMP | Record creation time |

## 4. Column Details

### 4.1 student_id
- Unique identification number for each student.
- Primary Key.
- Automatically generated by the database.

### 4.2 admission_number
- Official admission number of the student.
- Must be unique.
- Cannot be empty.

### 4.3 full_name
- Stores the student's full name.
- Maximum length: 120 characters.
- Cannot be empty.

### 4.4 section_id
- Connects the student to a section.
- Foreign Key referencing sections.section_id.

### 4.5 fingerprint_id
- Stores the fingerprint sensor slot reference number.
- Must be unique when assigned.
- Can be NULL if no fingerprint is registered.
- Do not store fingerprint images or biometric templates in this table.

### 4.6 date_of_admission
- Stores the student's admission date.
- Uses DATE format.

### 4.7 is_active
- TRUE means the student is currently active.
- FALSE means the student is inactive.
- Default value is TRUE.

### 4.8 created_at
- Records when the student entry was created.
- Automatically uses the database creation timestamp.

## 5. Relationships

- One section can contain many students.
- Each student belongs to a section.
- One student can have many attendance records.
- One student can be linked to multiple parents through student_parents.

## 6. Security Rules

- Only authorized administrators can add or edit student records.
- Teachers can view only their assigned students.
- Parents can view only their linked children's information.
- Use dummy student information during development.
- Collect only the personal information required by the school.
- Fingerprint information must be handled with appropriate authorization and security.
